# SEO优化

SEO优化是一个 Manifest V3 Chrome 扩展，用于在浏览器本地检查页面 SEO、站点抽样、国际 SEO、分析追踪和 SEM 数据，并把检测结果转成带代码解释的完整优化方案。主界面运行在 Chrome Side Panel，网页只注入按需采集器和独立 Shadow DOM 标注层。

## 能做什么

- 使用 `概览 → 问题 → 优化建议 → 海外站优化 → AI 深度解读 → SEM` 六个顶层视图。320px 侧栏显示紧凑标签，更宽侧栏显示完整名称。
- 点击插件图标后直接扫描当前网页并展示概览，不要求先输入网站地址、创建项目、填写市场、关键词、货币或广告信息。高级数据按当前域名自动归集；缺少业务上下文不会阻止基础扫描。
- 按六类规则计算页面 SEO 基础分：可发现与索引、元信息、内容语义、链接、媒体结构化数据、性能指标。它衡量当前页面可测的 SEO 基础信号，不代表实际收录或关键词排名。
- 概览内部按 `摘要 / 页面信息 / 页面数据 / 站点审计` 下钻。摘要展示页面 SEO 基础分、覆盖率与证据可信度、已通过项目、扣分项目、分类得分和本次访问性能；页面信息集中展示浏览器渲染后的元信息、正文结构、链接和媒体；“页面数据”依次解释搜索引擎访问、HTTPS 与正式地址、压缩与缓存、robots.txt、原始 HTML、结构化数据建议、CSS/JavaScript、nofollow 和检测边界；“站点审计”用于发现同一模板或一批页面共同存在的问题。
- 页面目标支持“保存目标并重新计算”和“重新扫描页面”两个独立动作。前者复用当前快照并反馈分数前后、规则变化以及不计分的解释字段；后者重新采集 DOM、HTTP 和本次访问性能，同时保留当前页面目标。
- 问题默认只显示失败和警告，分类数量跟随当前优先级和状态筛选。每条问题记录作用范围、证据来源和置信度；建议按根因聚合，说明一次修复影响多少条证据和 URL。
- “网站优化方案”按阻断、高影响、高置信度增长、风险候选和外部数据缺口排序。每项说明根因、证据、SEO/SEM 机制、推荐策略、修改层、直接结果、可能效果、不能保证的结果、验证和回滚，不把预期效果表述为排名承诺。
- 区分通过、警告、失败、信息、不可测和不适用，不把缺失证据当作失败。
- 增加不计入 100 分的“技术交付信号”：匿名 GET、HTTP/HTTPS 与 www/非 www 入口收敛、HSTS、混合资源、Brotli/gzip、分类缓存策略、robots 多爬虫规则、阻塞/重复资源和 nofollow。证书到期时间、证书链和 TLS 等级明确显示为浏览器扩展不可测。
- 代码方案说明适用技术栈、通常修改的文件或配置位置、修改前提、需要替换的变量、关键行含义、发布前检查、验证和回滚。可识别 WordPress、Shopify、Next.js、Nuxt/Vue、React SPA、静态 HTML、Nginx、Apache 和常见 CDN；证据不足时只展示最终输出目标和常见实现，不武断断言技术栈。
- 建议按根因合并同一问题，并提供页面访问与收录、标题内容与搜索意图、内链媒体与结构化数据、性能与资源加载、国际 SEO、数据追踪和 SEM 筛选。优化建议实时由当前证据生成，不创建负责人、截止时间、任务状态或执行队列。
- 在网页上定位可修复元素，不修改目标元素样式，也不造成页面布局位移。
- 复制 Markdown 报告或导出 JSON，不需要下载权限。
- 用户可主动运行同源“站点审计”。它默认选取最多 20 个代表页面，并可手动改为 50 或 100 页；遵守 robots.txt，优先当前页、首页、Sitemap 与不同目录/模板，并汇总 HTML 压缩、缓存、站内 nofollow 和匿名抓取信号，不将样本结果冒充完整全站结论。
- 可导入 Google Search Console、Bing、百度搜索表现 CSV，分析展现、点击、CTR、平均位置、排名 4–20 的增长页、本站同位置 CTR 基线、品牌/非品牌变化和查询页面冲突。这些外部数据不会进入页面 SEO 基础分。
- 海外站优化工作区分为 `概况 / 问题 / 优化建议 / 追踪`。概况按搜索访问、语言与地区、数据统计、广告与业务展示自动检查结论；确认问题和完整代码方案分别进入对应 Tab，追踪页集中承载标签证据、现场测试和三方报表核对。
- 单语言页面不会因没有 hreflang 被误报；缺少 GA4/GTM 只在需要衡量 Google/Bing 海外流量时作为条件性机会，没有投放证据时缺少 Ads/UET 不算问题。扩展会单独识别百度统计与 Clarity，但不会用它们证明 GA4、Google Ads、Microsoft Ads 或真实业务链路正常。
- 国际 SEO 在基础扫描时自动完成，并区分 hreflang 与移动版 alternate。同源及已经授权的关联地址会自动核对状态码、最终地址、Canonical、`noindex` 和 `html lang`；未授权跨域地址只进入检测边界，不会在自动扫描时弹出权限请求。
- Search Console、平台后台、真实搜索引擎抓取和服务器日志无法由浏览器直接确认的内容只列为检测边界，不伪装成插件结论，也不包装成强制操作任务。扩展不连接 Google/Bing OAuth，不读取相关账户。
- 追踪测试只有用户点击“开始测试”后才临时观察事件名、平台、相对时间和必要字段是否存在，最多 10 分钟或 200 条；用户完成成功和失败操作后自动停止并恢复页面函数，输出成功漏记、重复记录和失败误记候选。
- 海外数据核对支持 GA4、广告表现和业务结果 CSV，明确区分“页面存在标签 → 浏览器初始化 → 浏览器请求 → 平台确认收到 → 后端有效业务”五层证据。不会保存请求正文、表单值、Cookie、完整 dataLayer/uetq 或真实 event_id、lead_id、transaction_id。
- SEM 工作区分为 `概况 / 落地页 / 数据 / 诊断`，支持 Google、Bing、百度广告表现、创意和业务结果。诊断按追踪口径、搜索词、成本、创意与页面、有效业务、预算边界分析，并用普通语言解释 CPC、平台 CPA、有效 CPA、ROAS 和毛利回报；没有业务边界或成熟数据时只报告事实和风险，不生成调价或扩量结论。
- 修改页面后可重新扫描并比较新证据；技术检查通过仍不等于收录、排名或业务效果已经提升。
- 可选调用 OpenAI-compatible `/chat/completions` 接口进行按项目保存的多轮联合问答；域名、`/v1` 和完整接口路径都能自动识别。请求地址、模型和 API Key 配置完整后自动可用，AI 不影响本地规则、分数或 SEM 诊断。返回优先使用 SSE 流式输出，同时兼容非流式 JSON 响应。
- AI 发送后立即清空输入并显示本轮用户消息；回答会逐段显示，等待期间可以编辑下一条问题，也可以停止当前请求。较慢模型最长等待 120 秒，失败后会就地恢复草稿并提供重试。

## 权限

- `activeTab`：不授予长期网页权限时，仅在用户点击扩展图标后临时读取当前标签页。页面导航或重载后，这项临时授权会失效。
- `tabs`：识别当前活动标签页的 URL，确保从 Chrome 侧边栏入口打开时也能为当前网站申请授权。扩展不读取或保存浏览历史。
- `scripting`：按需注入页面采集器、标注层，以及用户主动开始追踪测试时的临时观察器。
- `storage`：会话内保存标签页报告；扩展本地存储保存网站记录、规范化 CSV 字段、站点审计与扫描基线、日志聚合结果、诊断、AI 配置、用户主动保存的 API Key 和网站对话。优化建议由当前证据实时生成，不保存任务状态。
- `sidePanel`：展示审计工作台。
- 可选主机权限：普通页面可由用户选择按域名持续授权；首次点击“允许检测当前网站”后，该域名可直接扫描和重新扫描。站点审计只申请当前项目 origin；相关语言页、移动版关联地址和用户配置的跨域转化域名只在用户主动检查对应功能时逐个按需授权，海外概况不会自动申请；“完整检查网站入口”只在点击后申请本次 HTTP/HTTPS、www/非 www 精确入口；AI 只为用户填写的 API 主机动态申请权限。拒绝后不会在每次扫描中反复询问，仍可用 `activeTab` 临时扫描当前页面。

Chrome 内部页、Chrome Web Store、PDF、跨域 iframe 和 closed shadow root 不可测。实际索引、排名、外链、全站重复、真实用户 CWV、搜索需求和转化率需要外部数据，不进入页面分数。

普通 HTTP/HTTPS 页面的索引目标默认为“未知”，避免把有意 noindex、404 等页面误判为 P0。页面类型会根据 JSON-LD 和分页信号自动识别，用户可在概览校正。单次访问性能采用 LCP、CLS、FCP、TTFB 与 viewport；需要真实交互样本的 INP 作为数据缺口，不进入本次分数。覆盖率低于 60% 时，页面 SEO 基础分会标记为“暂定 / 证据不足”。

## 搜索项目与本地数据

网站记录可包含主域名以及用户主动填写的市场、时区、货币、品牌词、核心转化、国际设置和 SEM 成本标准；未识别的市场、语言、货币和核心查询保持 `unknown`。页面报告保存在 `chrome.storage.session`；网站记录、规范化 CSV 行、站点审计、扫描基线、SEM 变更记录、服务器日志聚合、最近 20 次脱敏追踪测试和诊断报告保存在扩展 IndexedDB；AI 配置、Key 和对话保存在 `chrome.storage.local`。优化建议不作为任务持久化。IndexedDB v3 会保留并升级旧版项目、CSV、对话和站点审计结果；旧版整改记录仅为数据兼容保留，新版本不会继续创建。

CSV 使用标准解析器处理 BOM、引号、逗号和中英文表头，并在自动识别失败时要求确认字段映射。CSV 和服务器日志由 Web Worker 在本地解析，避免大文件阻塞侧栏；单个 CSV 上限为 20MB 或 100,000 行，日志上限为 20MB。扩展不保留原始文件，只保存用户映射的规范字段或日志聚合结果；邮箱、电话、姓名和地址等敏感字段不可映射，日志中的 IP、完整 Referer 和原始 User-Agent 不保存。用户可删除单个数据集、当前项目、当前项目对话、所有项目数据或全部扩展本地数据。

站点审计只请求同源 HTTP/HTTPS URL，读取原始 HTML 和允许列出的响应头摘要，不执行跨域抓取，也不是完整全站爬虫。请求使用匿名 GET，不发送 Cookie、Authorization、网页存储或表单值。它支持 Sitemap index、压缩 Sitemap、日期校验，并按目录和页面模板分层抽样；结果中的疑似孤立页、近似重复、模板问题、hreflang 和内链机会都受样本范围限制。当前浏览页仍单独提供渲染后 DOM、open shadow root、本次访问性能和最多 12 个同源 CSS/JS 响应头样本。

## 本地开发

```bash
npm install
npm run generate:icons
npm run dev:chrome
```

`dev:chrome` 会启动一个独立的 Chrome 调试实例，自动加载 `.output/chrome-mv3-dev` 中的开发扩展，并使用项目内已忽略的 `.chrome-dev-profile` 保存调试设置。不要在日常 Chrome 中重复手动加载开发目录。

该命令使用单实例锁。同一个项目已经有开发服务运行时，再次执行只会提示已有进程和使用方法，不会再启动第二个 Chrome，也不会出现 `CDP connection closed before response to Extensions.loadUnpacked`。

需要从任意终端接管服务时使用：

```bash
npm run dev:chrome:restart  # 停止现有实例并重新打开
npm run dev:chrome:stop     # 停止开发服务和专用 Chrome
```

也可以在启动服务的原终端按 `Ctrl+C` 正常停止。

### 使用已经打开的 Chrome

不希望 WXT 另外打开专用 Chrome 时，运行只启动热更新服务的模式：

```bash
npm run dev:chrome:manual:restart
```

然后在现有 Chrome 中打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择：

```text
/Users/mac/Desktop/TPProject/seoOpt-chrome-plugin/.output/chrome-mv3-dev
```

开发目录只需加载一次。以后运行 `npm run dev:chrome:manual` 并保持终端打开，保存 React/CSS 会热更新，后台、采集器或 Manifest 变化会重载扩展。侧栏被重载关闭时，重新点击工具栏中的“SEO优化”图标。

日常开发只需要保持运行：

```bash
cd /Users/mac/Desktop/TPProject/seoOpt-chrome-plugin
npm run dev:chrome
```

以后直接使用这条命令打开的调试 Chrome。修改并保存代码后，React 和 CSS 会热更新；后台、采集器或 Manifest 变化会触发扩展重载。扩展重载后侧栏如果自动关闭，重新点击工具栏中的“SEO优化”图标即可，不需要去 `chrome://extensions` 手动刷新。

开发服务器运行期间：

- 修改侧栏 React 或 CSS 后会立即热更新，通常不需要重新打开侧栏。
- 修改后台、页面采集器、Manifest 或公共资源后，WXT 会自动重建并重载扩展。
- 未授予当前域名持续权限时，扩展重载或页面导航会清除 `activeTab` 临时授权；可以再次点击工具栏图标临时扫描，也可以在侧栏中一次性授权当前域名。
- 在调试 Chrome 中按 `Alt+R` 可以手动重载扩展；终端按 `o` 后回车可以重启调试 Chrome，按 `Ctrl+C` 停止调试 Chrome 和开发服务器。

需要同时打开页面 DevTools 和输出详细构建日志时运行：

```bash
npm run dev:chrome:debug
```

如果 Chrome 安装在非默认位置，可以指定可执行文件：

```bash
CHROME_PATH="/path/to/chrome" npm run dev:chrome
```

Chrome Web Store 的正式版本使用另一套更新机制：修改 `package.json` 中的版本号、重新构建 ZIP 并在商店发布审核后，已安装用户会由 Chrome 自动更新。商店更新不是开发热更新，无法用本地保存代码直接推送给正式用户。

## 评分边界

总分为适用且可测规则的已得分除以满分。通过得满分、警告得一半、失败得零分；不可测和不适用退出分母。概览会列出本次规则获得分、可得分、扣分项和得分项；获得部分分数的警告会同时出现在得分与扣分视角。P0 索引阻断将总分封顶为 39，P1 索引风险封顶为 69，封顶原因与规则归一化分数分开显示。

## AI 数据边界

API Key 在用户点击“保存设置”后存入 `chrome.storage.local`，浏览器重启后仍然保留。界面只显示“是否已保存”，不会回显已保存的明文；用户可以在设置中单独清除 Key。请求地址、模型和 API Key 三项完整时 AI 自动可用；清除 Key 或清空地址、模型后将暂停使用，不会隐式删除历史对话。

只有用户在“AI 深度解读”中主动发送问题时，扩展才临时采集最多 4000 字可见短片段，并把当前页面全部规则证据、根因分组、规范化优化建议与代码方案、站点聚合问题以及 SEO/SEM/海外站摘要发送给用户配置的服务。不会发送原始 CSV、原始追踪请求、完整 dataLayer/uetq、真实事件或业务 ID、敏感字段值或完整站点 URL 列表。

对话优先按搜索项目 ID 保存在 `chrome.storage.local`，旧的 origin 对话会在域名匹配时迁移；未建立项目时仍按 origin 保存。最多保留最近 20 个会话、每个会话最近 20 条消息。每轮回答自动保存，也可手动保存或清除；重新扫描、切换同站页面或更新项目数据后，后续回答始终使用最新证据。报告过期时历史只读，重新扫描后才能继续发送。

扩展不发送完整 DOM、Cookie、本地存储、表单值、隐藏正文或页面脚本。发送给 AI 的页面信息被视为不可信数据，不能覆盖 AI 系统指令；返回内容以安全 Markdown 渲染，原始 HTML 被禁用，链接仅显示为不可点击文本。

插件界面固定使用浅色主题。设置中的“获取 API Key”入口会打开 `https://codecc.cc`，是否购买或使用该服务由用户自行决定。
